# Project reconciliation

Read this reference only when a Project is affected.

## Authoritative current state

The primary `<project>.md` page owns the present conclusion, status, plans, risks, owners, dependencies, open questions, and next actions. Reconcile changed state by replacing or removing superseded material. Retain history there only when it still explains an active decision, constraint, risk, dependency, or unresolved question.

A Project uses one `index.md`, one primary page, and only `notes/` and `decisions/` when supporting records are needed. Do not create parallel state, log, or inbox folders.

## Supporting records

- **Notes** retain evidence, commitments, unresolved work, or context that remains useful independently of the primary page. Integrate and remove raw status dumps after they lose unique value.
- **Meeting notes** are point-in-time records. Retain meetings with meaningful decisions, commitments, discoveries, or unresolved issues. Change retained meeting notes only for explicit corrections.
- **Decisions** retain consequential choices whose rationale remains useful. A superseded decision keeps its original rationale, uses `status: superseded`, and links to its replacement; the replacement links back.
- **Source notes** retain provenance when external material materially supports current knowledge and remain governed by `second-brain-ingest`.

## Index

Organize retained pages by role and describe their content. Do not present the Project index as an activity feed. Update it only when navigation, lifecycle, listed summary, or listed status changes.
