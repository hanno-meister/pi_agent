# Glossary

## Linked project

The single project under `/pi_agent/workspaces/second_brain/10-projects/` referenced by the managed second-brain block in a code repository's root `AGENTS.md`.

## Project-level knowledge

Durable knowledge that changes the linked project's outcome, status, product or domain decisions, user-visible behaviour, constraints, risks, open questions, or next steps. Implementation details remain in the code repository unless they materially affect this understanding.

## Current project state

The authoritative present-tense conclusion, status, risks, and next steps recorded on the linked project's primary page and applicable owned pages. It replaces superseded information rather than accumulating an update log.

## Project record

A durable point-in-time note or decision retained because its evidence, rationale, commitment, or unresolved context remains useful after the current project state is updated.

## Update proposal

The exact set of second-brain paths and content-level operations that `/update-second-brain` presents for approval before changing the vault.

## Project decision

An accepted choice about scope, product behaviour, domain language, external constraints, project-level architecture, or delivery direction that would remain meaningful if the implementation were replaced. Refactors, file structures, libraries, tests, and code mechanics are implementation details rather than project decisions.

## Project milestone

A meaningful project outcome already represented by the vault, such as a validated prototype or an operational workflow. A completed commit or ticket is not a milestone by itself.
